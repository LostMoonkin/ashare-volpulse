# 标准模式悬浮窗拖动缩放与窗口自适应

## Goal

当前桌面悬浮窗（HUD）在标准模式下被锁定为固定尺寸（`400 × 456`），用户监控较多自选股或长名称 ETF 时需要频繁滚动或查看被截断的标的名称，无法按屏幕空间自由调整悬浮窗大小。

完成后，用户可在**标准模式**下直接拖动悬浮窗四边或四角自由缩放窗口尺寸，界面内容随窗口大小自动适配（拉宽显示更长名称、拉高显示更多自选股），且自定义尺寸持久化保存并在重启或切换模式后自动恢复；**极简模式**继续锁定紧凑尺寸、不允许缩放。

## Behavior

**标准模式自由缩放与持久化**
- 标准模式下悬浮窗允许拖动四边或四角缩放，尺寸限制在最小 `340 × 360` 至最大 `720 × 960`（且不超过当前显示器工作区尺寸）之间。
- 缩放过程中防抖持久化新的窗口尺寸与坐标（拖拽左/上边缘缩放时同步保存新位置），应用退出前立即刷盘，重启后自动恢复上次自定义的标准模式尺寸与位置。
- 窗口内容采用自适应布局：
  - 拉宽窗口时，标的名称列自动获得更多展示宽度，减少长股票名/ETF 名截断；
  - 拉高窗口时，自选股列表区域自动增高并展示更多可见行；
  - 缩窄至最小宽度时，顶栏操作按钮、核心指标与行情数值列保持可读不溢出。

**极简模式与模式切换**
- 极简模式始终保持固定紧凑尺寸（`320 × 212`）且禁止用户拖拽缩放。
- 从标准模式切入极简模式时，保留用户已调整的标准模式尺寸（不覆盖为极简尺寸），按原有左/右边缘锚点缩小并锁定缩放。
- 从极简模式切回标准模式时，恢复用户上次保存的标准模式自定义尺寸（无自定义记录时使用默认 `400 × 456`），重新开启自由缩放，并确保窗体完整留在当前显示器工作区内。

**多屏与异常恢复**
- 启动恢复、老板键恢复或从外接高分屏切回较小主屏时，若已保存尺寸超出当前显示器工作区，自动钳制在可用工作区内。

## Constraints

- 保持 Electron 进程隔离（`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`），配置持久化写入本地 SQLite `app_settings`。
- 不改变既有沪深总成交额口径、行情轮询频率、告警逻辑与极简模式「仅显示总成交 + 最多 3 条自选股」行为。
- 顶部拖拽区不得吞掉标准模式窗体上边缘的原生缩放命中区，且程序切换模式期间触发的窗口尺寸变更不得污染已持久化的标准模式尺寸。

## Out of Scope

- 极简模式支持手动缩放或修改极简模式 3 条自选股上限。
- 字体、图标随窗口尺寸做等比缩放（缩放仅做布局自适应）。
- 在设置页或托盘新增自定义预设尺寸模板（后续按需再扩展）。

## Acceptance Criteria

- 标准模式下 HUD 窗口创建时 `resizable` 为 `true`，最小尺寸为 `340 × 360`；极简模式下创建或切换后 `resizable` 为 `false`，尺寸锁定为 `320 × 212`。
- 用户在标准模式拖拽缩放后，尺寸与坐标经防抖持久化写入 `app_settings`（退出前立即刷盘）；重启后以保存尺寸恢复，超出当前工作区时自动钳制。
- 标准模式 → 极简模式 → 标准模式往返切换后，能精确恢复切换前的标准模式自定义尺寸并保持左/右边缘对齐，且切入极简模式不会污染已保存的标准模式尺寸。
- 详情浮层弹出位置计算自动基于 HUD 当前实际缩放后的尺寸贴边避让。
- `npm run typecheck`、`npm run test`、`npm run build` 全部通过，且覆盖几何钳制、设置持久化及 `WindowManager` 缩放/模式切换/刷盘单元测试。
